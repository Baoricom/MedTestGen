MedTestGen app map

A compact reference for the finished proof of concept: one synthetic CT order becomes linked DICOM CT, HL7 ORM^O01 and FHIR R4 output, then passes backend-controlled validation before ZIP export.

Generate Dataset: one action through the system

1. Browsermedtestgen/static/app.js
generate() sends the prefilled form, session revision and request ID.
2. API + candidatemedtestgen/main.py
generate() obtains a store ticket and calls build_dataset().
3. Generate + validatemedtestgen/pipeline.py
DICOM, HL7 and FHIR are built from one scenario; mandatory and external checks produce the report.
4. Promote + exportmedtestgen/store.py and export.py
finish() promotes only eligible data; download() rechecks every export gate.

Reference route

  1. Input and visible result. Open medtestgen/static/app.js and find generate(event), then renderDataset(data). These functions connect the button to the API and display the real validation states without converting NOT VERIFIED into PASSED.
  2. Canonical generation and evidence. Open medtestgen/pipeline.py and find build_dataset(). It creates all three standards from one scenario, performs readback, HL7, FHIR, consistency and per-instance dciodvfy checks, then prepares the ZIP in memory.
  3. Atomic replacement and backend enforcement. Open medtestgen/store.py and find finish() and download(); then inspect eligible() in medtestgen/export.py. The active dataset pointer changes only after successful generation and validation, and direct ZIP requests cannot bypass the same policy.

To change this, start here

  • CT pixels and required attributes: medtestgen/generators/dicom_ct.py → generate_ct().
  • DICOM/HL7/FHIR identifier mappings: medtestgen/models.py, the three files under medtestgen/generators/, and devpost/mappings.md.
  • Validation and ZIP authorization: medtestgen/validation/ and medtestgen/export.py → eligible().
  • TTL, memory limits and concurrency: medtestgen/config.py and medtestgen/store.py.
  • Labels, layout and previews: medtestgen/static/index.html, styles.css and app.js.

A practice to reuse

Turn a safety rule into an observable backend predicate and test its bypass path. Here, the approved rule “Never silently export data that failed mandatory validation” is implemented by eligible() and exercised through direct ZIP API tests in tests/test_api_export.py. The same pattern applies to permissions, payments or any workflow where disabling a button alone is insufficient.

Run it again

From PowerShell in the repository:

.\.venv\Scripts\Activate.ps1
python -m uvicorn medtestgen.main:app --host 127.0.0.1 --port 8000 --workers 1

Open http://127.0.0.1:8000. Run tests with python -m pytest -q.
